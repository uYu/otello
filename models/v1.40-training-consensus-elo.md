# v1.40 数据候选：多走法、多结果与内部 Elo

用户最新决定：先讨论 Elo 的用法，不启动新模型训练。所有下述产物属于数据准备和试算；加权规则未被选为下一轮训练方案。默认仍为冻结的 v1.37 对称共享模型。

## Elo 是如何计算的

已知参与者统一初始化 1500，K=32，尺度 400：

`E_A = 1 / (1 + 10^((R_B-R_A)/400))`

`delta = K * (S_A-E_A); R_A += delta; R_B -= delta`

S 是实际得分，胜 1、平 0.5、负 0，绝不是直接加到评级上的分数。例如同为 1500 时，胜者加 16、败者减 16，平局均不变。K、初值和连续 logistic 预期公式是本项目内部估计的设置，不是官方 WOF 或 FIDE 等级分。实际得分与预期得分之差乘 K 的更新形式可参考 [FIDE 说明](https://handbook.fide.com/chapter/B022024)，本项目不复制其整套分段 K、入场评级及分差表规则。

- 给名册中 4,447 个非零编号初始化，包括参与者和程序。4,222 个编号有可识别的完整比赛；其余保留初值。
- 描述性评级重放 136,100 盘完整、双方可识别且编号不同的 WTHOR 比赛。编号 0 表示未知参与者，不能合成一个人；不完整棋局也不更新。
- 另算只由原始 train split 更新的独立评级池，共 79,955 盘。完整语料评级只用于查看，不能直接用于训练权重。
- 排序为年份、原始记录序号、game ID。数据没有精确对局日期；同年内逆序重放时，至少 20 盘者的最终评级 RMS 差为 30.39 分，说明文件顺序确实影响结果。
- 若未来使用评级给标签加权，试算字段采用年初的 train-only 评级及此前盘数，排除当年赛果、该盘胜负、验证和测试集赛果。另保留逐盘赛前评级供检查。
- 2,901 个有有效比赛的编号不足 20 盘。评分只是样本内相对估计，支持盘数需一起看。对局图包含 13 个连通分量，最大分量 4,196 个编号，小分量之间没有充分的绝对强弱标尺。

## 多标签保留结果

独立回放完整训练棋谱 141,336 盘、8,593,796 个行动。原始候选出现记录 2,259,884 条，排除冻结 holdout 所持局面的 199,576 次出现后，保留 2,060,308 条记录、1,255,303 个相对颜色/D4 规范化局面。

- 24,857 个局面有多种实战走法轨道；34,038 个有多种终局胜平负记录；25,327 个既有胜又有负的记录。
- 与原训练百万局面逐行对应的视图也已保存，其中多走法轨道 19,829 个、多结果 27,154 个。
- 每个局面保存全部原始胜/负/平计数、稀疏走法质量、来源计数和每次出现的 game ID 索引。
- 对称稳定子等价落点均分一条记录的质量，避免规范化任意选向造成假偏好。展开对称等价落点后有 24,896 个多落点局面，不要与 24,857 个实战走法轨道数混用。
- 每次出现还保留落子者/对手编号、实际落子颜色、阶段、train-only 年初评级与盘数。处理了强制 pass，原始来源和哈希可追溯。
- 冻结验证/测试局面交叉为 0；稀疏策略标签非法落点为 0；原始缓存和模型哈希保持不变。

## 仅供讨论的 Elo 用法试算

原始多走法/多结果计数一直保留。额外生成了一份可弃用的试算：

`q = .5 + min(priorTrainGames/20, 1) * (EloExpected(actorYearStartElo,1500)-.5)`

没有棋手 ID、没有此前盘数时使用中性值 .5。无 ID 的 Logistello 记录不会凭来源名称合成棋手评级。这里只对策略质量做试算，不使用落子者 Elo 重写实际胜负。

试算同时导出了质量加权的策略分布和每个局面的平均质量。只改变概率分布不足以压低单标签弱手样本的影响，因为归一化后其落点概率依然是 1；因此另保存平均质量相对中性值的损失权重。是否采用这一公式、用何阈值、盘数如何影响置信度，以及是否用引擎检查着法，都留待讨论。本轮没有据此训练或删除低分棋谱。

经验胜负分布的标量均值是 P(胜)-P(负)，不是完美博弈价值。若以后训练，应直接使用软价值/WDL分布，不可再次对软均值取 sign；冻结验证/测试集仍沿用原标签。

## 关于 MLP 与 tiny_nn

实测 MLP8/16/32 库的 `OTELLO_PATTERN_SIMD` 和 `OTELLO_PATTERN_BLOCK4` 均为 ON，库为 arm64。Pattern 的 INT16 dot 已使用 `cpp/pattern_kernels.hpp` 中的 NEON/SSE2；它没有直接调用 FP32 `cpp/model/tiny_nn.h`。

从代码计算结构看，每个合法落点的 MLP、局部特征聚合和量化增加了工作；策略层目前仍逐隐藏单元 dot，可研究四行复用。尚未做分段耗时 profile，因此各部分占比未知，不能把实测变慢直接归因于没有使用 tiny_nn。未切换推理路径或修改已冻结计时实验。
