# v1.8：棋形 NNUE＋策略／胜负和／子差多头实验

本记录作为独立的附加实验 `rapfi-inspired-pattern-multihead-20261029` 保存，起点为提交 `8059d4496da568fb00b1f1cc5fd557e9ecf4fbef`。文件名中的 `v1.8` 仅为本次实验的本地标识，不用于排列其他机器上独立实验的版本顺序；本轮未切换默认模型。

本轮采用受 Rapfi 启发、独立实现的黑白棋棋形网络。训练、推理和 60 局等时限对战已完成，逐手记录见 `v1.8-pattern-matches.json`。默认仍使用 v1.3 NNUE＋MCTS。

## 结构

- 38 个棋形：8 行、8 列、18 条长度 4～8 的对角线、4 个朝棋盘内部定向的角部 3×3。
- 每格按空／己方／对方编码为三值数字。行列按离边距离共享 4 套表，对角线按长度共享 5 套表，角部共享 1 套表，共 55,728 个索引，每个索引为 32 维可学习向量。
- 4 条边线、30 条内部线、4 个角部各自取均值，得到 96 维；拼接剩余空格数／60，进入 `97→32` 的 clipped-ReLU 主干。
- 子差头为 `32→1/tanh`；胜负和头为 `32→3/softmax`。
- 策略头由全局主干生成 32 维门控及 10 类位置偏置；各落点汇总包含该格的棋形向量，与门控点积，再加位置偏置。非法落点在损失和搜索 softmax 前屏蔽；强制停着直接处理，不训练 pass 输出。
- 表和线性权重为 int16，偏置／累加器为 int32，点积使用 int64。量化尺度 256，训练使用直通量化；支持落子、翻子、停着后的增量累加器维护。

这是直接学习的棋形向量表，未复刻 Rapfi 的方向卷积训练器、完整 Mix10 架构或棋形参数。也未引入其代码或五子棋权重。方法参考 [Rapfi Mix10 推理](https://github.com/dotb1ue/rapfi/blob/1387d11312190ec66665d361ff07a7c70221b78a/Rapfi/eval/mix10nnue.cpp)及[配套模型定义](https://github.com/dotb1ue/pytorch-nnue-trainer/blob/ed6ff57cbd9d31bc5217ecbdf0de2a004c6be374/model/mixnet.py#L1026)。

## 训练与冻结数据

使用与原 NNUE 完全相同的百万训练局面、验证／测试各 6,000 局面，缓存 SHA-256 为 `ed971def0db9636494a8c1fe46f9b86fb053adfe546b62e699b463282c4c8ec6`。下一手标签从原棋谱中匹配相同颜色相对棋盘、最终结果和原始 split 的第一条记录；全部 1,012,000 行成功匹配并核对合法性。原有子差标签、开局分组与对称去重保持不变。

训练仅对训练集做 D4 增强，同时变换棋盘、下一手和合法落点掩码。策略标签是实战下一手，不代表唯一最优解；价值标签仍为实战最终子差，没有教师重标或自对弈重训。数据归属与使用约束沿用 [data/README.md](../data/README.md) 和原始 manifests。

CPU 训练 15 轮，batch 2048，AdamW lr 0.001，权重衰减 0.0001，种子 20261029。损失为 `子差 MSE＋0.1×胜负和交叉熵＋0.1×合法落点策略交叉熵`。按最低验证子差 MSE 选择第 13 轮，未用测试集或对战结果选权重。原 NNUE 训练 30 轮；本轮不主张相同训练计算量。

## 推理速度与一致性

相同的 64 个冻结测试局面，7 轮、每轮 4,096 次，交错测试顺序。完整重建估分中位数：原 NNUE **1.650µs**，棋形网络 **1.882µs**。棋形网络同时输出子差、胜负和概率及 64 个策略 logits 为 **2.657µs**。

上述数字包含 Python／C ABI 开销；完整三头接口还包含 WDL softmax 和输出拷贝。AB 中两种网络都能增量更新，不能用完整重建耗时比替代实际搜索吞吐。测量时无并行训练或对战。

全部 6,000 个冻结测试局面通过 Python／C++ 三头对照：最大归一化子差差 2.97e-08，最大 WDL 概率差 1.33e-07，最大策略 logit 差 6.23e-07；C ABI 整数估分最大取整误差 0.497253 分（满尺度 1,000）。

## 每手 100ms 的三组对战与策略消融

三组使用同一个原生库，单线程、依次走棋，标准四子初始棋盘，不使用指定开局、开局库或其他引擎兜底。每个配对 20 局、10 组种子交换黑白，总计 60 局。前 12 次落子沿用共同的近分加权开局选择；局内保留实际到达子树，每局清空缓存。探索系数 1.5，最多 2,097,152 个访问节点。

| 行方对列方 | 胜 | 平 | 负 | 得分率 | 平均子差 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 棋形网络＋均匀先验 对 原 NNUE＋均匀先验 | 12 | 0 | 8 | 60.0% | +1.65 |
| 棋形网络＋策略先验 对 原 NNUE＋均匀先验 | 16 | 1 | 3 | 82.5% | +4.70 |
| 棋形网络＋策略先验 对 棋形网络＋均匀先验 | 11 | 2 | 7 | 60.0% | +3.15 |

关闭／开启策略先验的两个棋形组使用完全相同的权重。开启时同时使用合法落点策略 softmax 与有限 FPU（父节点均值减 0.15）；关闭时保留原有均匀先验、未访问分支优先规则。因此这是“策略先验＋FPU”的联合消融，没有单独分离两者贡献。搜索仍回传子差／64，胜负和头作为训练辅助，未用作搜索价值。

| 组合 | 平均实际耗时／手 | 平均模拟次数／手 | 平均网络评估次数／手 |
| --- | ---: | ---: | ---: |
| 原 NNUE＋均匀先验 | 91.65ms | 296,233 | 42,036 |
| 棋形网络＋均匀先验 | 90.63ms | 280,820 | 42,013 |

全部 3,630 个动作通过独立逐格规则重放；合法落子、停着、终局子差、种子、配对颜色、开局加权选择、根访问数与最终选择均已核对。共有 60 种完整棋谱。模拟次数包含重复已知终局的回传，不能等同网络调用次数。100ms 是上限，精确求解或节点上限会提前停止。

这份初步结果支持继续探索棋形多头网络与策略引导；样本只有每对 20 局，均从初始棋盘开始，不能推广为稳定胜率或 Elo。新旧训练轮数和损失不同，本轮也不能独立归因于棋形结构或多任务训练。新模型约 3.58MB，显著大于旧 NNUE；默认对手保留原模型。

## 运行与复现

```sh
cmake -S . -B .build/native-v1.8 -DCMAKE_BUILD_TYPE=Release
cmake --build .build/native-v1.8 -j 2
ctest --test-dir .build/native-v1.8 --output-on-failure
.build/native-v1.8/otello analyze --network models/pattern32-v1.8.otpat --time 100
# 显式选择 AB，同样使用棋形子差头：
.build/native-v1.8/otello analyze --network models/pattern32-v1.8.otpat --search ab --time 100
npm run test:pattern
npm run test:baseline:v1.8
```

重新训练时为模型选择新路径，避免覆盖冻结产物：

```sh
npm run training:run:pattern -- --output .build/training/v1.8-rerun/pattern.otpat
npm run training:benchmark:pattern -- --output .build/training/v1.8-rerun/benchmark.json
npm run training:baseline:v1.8 -- --output .build/training/v1.8-rerun/matches.json
```

默认比较脚本加载本轮冻结模型；训练重跑的独立文件可通过 CLI 的 `--network` 指定。Linux 使用 `.so`，脚本按平台选择默认库后缀。新模型可经原生 CLI／C ABI 加载，网页继续嵌入原来的默认模型。

测量源码保存在 `archive/v1.8-sources.tar.gz`，逐文件哈希见 `v1.8-baseline.json`。测量后仅修正原生 CLI 的 evaluator 显示名，使其标为 `othello-pattern32-v1.8`；该主程序文件不属于实测共享库，库字节与对战时完全相同。修正前后主程序哈希也记入基线。
