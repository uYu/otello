# CNN 与 v1.9 的共同批处理诊断

两边均使用同一 C++ MCTS 批次收集、临时访问预留、回传逻辑与单线程 Apple Accelerate 矩阵后端。
固定原验证局面；4 个局面按相同 8,192 模拟预算比较 batch 1/8/16/32/64，
两边在该短诊断中吞吐最佳均为 batch 32。另在相同两个局面上各用 2 秒比较原实现、batch 1、batch 32。
CNN 仍是 `cosine-joint` 原权重，NNUE 仍是批准的 v1.9 原权重，没有重新训练或改变默认。

下表是两个固定验证局面、2 秒预算下的平均模拟数：

| 实现 | CNN | v1.9 NNUE |
|---|---:|---:|
| 原实现 | 50,853 | 235,741 |
| 新矩阵后端，batch 1 | 125,788 | 602,338 |
| 共同后端，batch 32 | 191,440 | 1,147,828 |

双方都有明显工程收益，v1.9 同样受益；不能把“CNN 新实现优于 CNN 旧实现”的倍数当成对 v1.9 的棋力优势。
这只是少量固定局面、当前正式 CPU 对战仍在运行时的诊断。不同模型搜索路径和精确证明停止情况也不同，
模拟数不等同于棋力。大 batch 会延迟回传反馈，同模拟预算下可能搜索得更浅。

NNUE 的整数特征变换在 FP32 可精确表示范围内做矩阵乘；策略隐藏层先证明整数运算界限，
超过精确范围则回退 int64。价值头保留 int64，策略输出保留 double。
本次 NNUE 所收集叶节点与原推理价值／策略输出误差均为 0；batch 1 的固定模拟走法、评分、根访问一致。
CNN 批处理与原推理的最大整数价值误差为 0，策略概率误差约 1.19e-6。

此前 Python/MPS GPU 原型在这一小网络上受到调度和拷贝开销影响，batch 32 只有约 0.70 万模拟/秒，
低于原 CPU 的约 2.51 万。原生批量矩阵实现去除了这一路往返。
更早的逐步扩展走法原型，在 8 个局面、各 1,024 模拟下平均深度从 4.60 到 5.01，但未测棋力。
这些记录分别保存在 v1.16/v1.17/v1.18 诊断 JSON，不混同正式对战。

候选库全部位于独立 experiments／.build 目录，正在运行的 v1.14 两组原协议对战及默认模型保持原样。
源码归档保留各次实测版本；v1.17 测速后补充的测试 CMake 单独保留，实测 CMake 哈希不改写。
