# v1.1 NNUE 对战 v1 NNUE

2026-10-27 完成。v1.1 作为搜索优化的小版本发布，包与 CMake 项目版本为 1.1.0；NNUE 沿用 v1 的 256 维模型，未训练或替换权重。启发式引擎保留作为较弱的玩家对手，本次不评测启发式棋力。

## 结果

统计视角为 v1.1：**52 胜、3 平、45 负，得分率 53.5%，平均子差 +4.48**。

| v1.1 执子 | 局数 | 胜 / 平 / 负 | 得分率 |
| --- | ---: | ---: | ---: |
| 执黑 | 50 | 6 / 2 / 42 | 14.0% |
| 执白 | 50 | 46 / 1 / 3 | 93.0% |
| 合计 | 100 | 52 / 3 / 45 | 53.5% |

这组结果为小幅领先，不能据此认定稳定的棋力优势。100 局全部从同一个初始棋盘开始，共有 **23 种不同的完整棋谱**；其余为重复棋谱。本组执子颜色和固定起点轨迹对结果影响明显，不将这些重复对局视为独立开局样本，不推算 Elo 或统计显著性。时间限制搜索会受机器负载和计时波动影响。

## 搜索表现

| 指标 | v1 | v1.1 |
| --- | ---: | ---: |
| 实际搜索步数 | 3,000 | 3,000 |
| 总节点数 | 189,932,494 | 218,063,162 |
| 节点吞吐量 / 秒 | 1,511,087 | 1,753,693 |
| 平均完成深度（排除已精确求解的步骤） | 6.985 | 7.265 |
| 平均每步实测耗时 ms | 41.898 | 41.448 |

本组对战中，v1.1 节点吞吐量提高约 **16.1%**，未精确求解步骤的平均完成深度提高约 **0.28 层**。两边实际走到的局面并非完全相同，这些为对战过程中的描述性统计。另有相同局面、相同深度的受控性能测试，NNUE 连续局面搜索约加速 **1.21 倍**，所有候选评分与 v1 一致，详见 [性能记录](v1.1-search.md)。

## 对战设置与复核

- 共 100 局，v1.1 交替执黑/白，各 50 局。双方每步各 50ms，最大深度 64，等级 2，搜索种子固定为 1。
- 全部从标准四子初始棋盘开始，第一步起均由算法决定；不预设开局走法、不使用开局库、不引入随机开局。
- 两边加载同一份 `models/nnue256-v1.otnnue`。v1 从带校验值的原始源码归档重建，v1.1 从当前源码构建，均使用 Apple Clang 16、CMake Release。
- 每个版本运行在独立的常驻进程里，逐步、逐局顺序运行。每局开始清表；v1.1 在本局内跨自己的走棋步骤复用置换表。v1 按原实现每次搜索重新建表。
- 独立的 Python 八方向规则实现检查每一步，并重放全部 **100 局、6,013 个动作**，复核停着、终局棋盘、子差、胜平负及引擎归属。节点数、命中数、平均深度与耗时亦从逐步记录重新汇总核对。

完整逐局记录见 [v1.1-vs-v1-nnue.json](v1.1-vs-v1-nnue.json)，版本校验清单见 [v1.1-baseline.json](v1.1-baseline.json)。原始 v1 基线、模型和两组历史对战报告保持冻结。

## 复现与监控

先按[性能记录中的命令](v1.1-search.md#复现)构建两个版本，再运行：

```sh
npm run training:baseline:v1.1 -- --output .build/v1.1-evaluation/repeat.json
npm run training:watch:v1.1
npm run test:baseline
```

对战程序默认拒绝覆盖已有报告。监控命令显示本次冻结报告，重跑的实时状态位于新输出文件旁的 `.live.json`。退出监控不会停止对局。
