# v1.1 搜索性能记录

v1.1 实现四项一桶的置换表、同线程跨次搜索复用、固定数组走法排序和延迟 NNUE 累加器更新。每线程置换表条目的总预算保持 8 MiB；历史表仍在每次搜索时重新初始化。模型沿用 v1 权重，未训练新模型。启发式引擎保留为较弱的玩家对手，后续版本棋力对比只测 NNUE。

缓存按模型内容隔离，切换评估器或修改参数会清表。较深记录可以用于排序，但只有与本次请求相同深度的分数才能直接截断，以保持固定深度的所有根候选评分准确。

## NNUE 固定深度对比

Apple Clang 16、macOS arm64、CMake Release。深度 6、不设时间限制；两个固定随机棋谱种子为 91 和 2026。每组 8 个局面，重复 7 轮，交替运行新旧引擎，表中为每轮总耗时的中位数（毫秒）。所有请求均比较了最佳分数和每一个候选走法分数，全部一致。这些局面只用于测计算速度；正式对战全部从标准初始棋盘开始，由算法决定每一步。

| 缓存场景 | v1 总耗时 ms | v1.1 总耗时 ms | 加速比 |
| --- | ---: | ---: | ---: |
| 空表 | 133.60 | 113.51 | 1.18× |
| 连续局面 | 226.14 | 187.32 | 1.21× |
| 重复同一局面 | 130.27 | 28.70 | 4.54× |

空表场景选取每盘落子 12、24、36、48 手后的局面，每次请求前清空 v1.1 表；清表耗时不计入搜索计时，v1.1 复用已分配的内存。v1 原本每次请求都会重新分配和初始化表，该开销属于其请求耗时。连续场景选取每盘落子 24、25、26、27 手后的局面，组内保留缓存。重复场景在每个局面上预热一次再测第二次，代表重复分析的有利情形。

这是小样本性能基准，加速比例不代表所有局面，更不代表棋力或 Elo 提升。原始节点数、命中数、模型和库哈希、当前源文件及 Wasm 校验值见 [v1.1-search-baseline.json](v1.1-search-baseline.json)。v1 原始实测记录、模型及基线文件保持原样；对应源码保存在带校验值的 [归档](archive/v1-sources.json) 中。

## 复现

```sh
mkdir -p .build/v1.1-evaluation/v1-source
tar -xzf models/archive/v1-sources.tar.gz -C .build/v1.1-evaluation/v1-source
cmake -S .build/v1.1-evaluation/v1-source -B .build/v1.1-evaluation/v1-native -DCMAKE_BUILD_TYPE=Release
cmake --build .build/v1.1-evaluation/v1-native --target othello -j 2
cmake -S . -B .build/native-v1.1 -DCMAKE_BUILD_TYPE=Release
cmake --build .build/native-v1.1 -j 2
python3 scripts/benchmark-search.py --before .build/v1.1-evaluation/v1-native/libothello.dylib --after .build/native-v1.1/libothello.dylib --evaluator nnue --depth 6 --rounds 7 --output .build/v1.1-evaluation/performance.json
npm run test:baseline
```

Linux 将两个库路径的 `.dylib` 改成 `.so`。基准脚本只依赖 Python 标准库及已构建的原生库。
