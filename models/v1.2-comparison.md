# v1.2：让 NNUE 考虑轮到谁走

2026-10-27 完成模型修改、重新训练和对 v1.1 的 100 局对战。v1.2 从当前行棋方视角分别使用双方特征，解除旧模型对同一棋盘换行棋方时必须只反号的限制。保留 v1.1 的 PVS、置换表、排序、时间预算和搜索选项；不增加隐藏层、阶段头、新特征或新训练标签。

| v1.2 执子 | 局数 | 胜 / 平 / 负 | 得分率 |
| --- | ---: | ---: | ---: |
| 执黑 | 50 | 49 / 0 / 1 | 98.0% |
| 执白 | 50 | 19 / 0 / 31 | 38.0% |

本组条件下，新模型明显领先 v1.1。100 局全部从同一个初始棋盘开始，只有 **13 种不同的完整棋谱**，包含大量重复对局；不作为独立开局样本，不推算 Elo 或统计显著性，也不据此承诺对任意对手或局面的优势。时间限制搜索会受系统负载与计时波动影响。

## 对战协议和复核

- NNUE 对 NNUE，各使用对应的冻结模型；不评测启发式引擎，不启用开局库。
- 标准四子初始棋盘，不预设开局、不随机安排前几步，第一步起完全由算法自行选择。
- 双方每步各 50ms，最大深度 64、等级 2、搜索种子 1；交替颜色，各执黑/白 50 局。
- v1.1 从校验过的源码归档重新编译，v1.2 从当前源码编译，均为 Apple Clang 16、CMake Release。两边分别运行在常驻进程里，逐步逐局顺序运行，避免互相抢占计算预算。
- 每局开始清空双方置换表，局内保留跨步复用。独立 Python 八方向规则检查落子、停着、终局；重放 **100 局、6,103 个动作**，核对子差、胜负、选步引擎和最终棋盘。逐步搜索统计也重新汇总核对。

## 重现

```sh
python3 scripts/data-assets.py restore
mkdir -p .build/v1.2-evaluation/v1.1-source
tar -xzf models/archive/v1.1-sources.tar.gz -C .build/v1.2-evaluation/v1.1-source
cmake -S .build/v1.2-evaluation/v1.1-source -B .build/v1.2-evaluation/v1.1-native -DCMAKE_BUILD_TYPE=Release
cmake --build .build/v1.2-evaluation/v1.1-native --target othello -j 2
cmake -S . -B .build/native-v1.2 -DCMAKE_BUILD_TYPE=Release
cmake --build .build/native-v1.2 -j 2
npm run training:baseline:v1.2 -- --output .build/v1.2-evaluation/repeat.json
npm run training:watch:v1.2
npm run test:baseline
```

要从头重训，先按训练文档重建并校验 v1 百万局面缓存，再运行 `npm run training:run:v1.2`；输出位于 `.build/training/v1.2/`，不覆盖发布权重。Linux 训练命令的库后缀改成 `.so`，对战程序会自动选择本机库后缀。加载与推理兼容原 `OTNNUE1` 和新 `OTNNUE2`，C ABI 输出布局不变。
