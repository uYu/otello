# v1.3：保留衰减开局随机选步

2026-10-27 完成。使用的仍是 **v1.2 考虑行棋方的 NNUE 模型**，权重 SHA-256 与 v1.2 完全相同；没有重新训练，也没有改回旧结构。v1.3 只增加对弈选步策略。

## 取舍与结果

新策略对原版 v1.1，100 局 **68 胜、1 平、31 负，得分率 68.5%，平均子差 +3.58**。按用户允许小幅棋力损失以换取多样性的偏好，结合本组仍领先 v1.1 且重复减少的结果，保留该策略并默认用于原生 NNUE 自对弈。

| v1.3 执子 | 局数 | 胜 / 平 / 负 | 得分率 |
| --- | ---: | ---: | ---: |
| 执黑 | 50 | 33 / 0 / 17 | 66.0% |
| 执白 | 50 | 35 / 1 / 14 | 71.0% |
| 合计 | 100 | 68 / 1 / 31 | 68.5% |

本次没有采用“必须达到 50%”的硬门槛。既往 v1.2 最高分选步对 v1.1 的得分率为 68%，本次为 68.5%；两组覆盖的局面与时间波动不同，不能用二者相减来量化随机性的棋力损失，也不能据此声称随机策略提升了整体棋力。更直接的结论是：在这组预算和起点下，增加变化后仍保持对 v1.1 的优势。

## 变化是否增加

| 指标 | 原 v1.2 最高分选步的 100 局 | 本次 v1.3 的 100 局 |
| --- | ---: | ---: |
| 不同完整棋谱 | 13 | 41 |
| 对称去重后的完整棋谱 | 13 | 41 |
| 前 12 次落子序列，对称去重 | 5 | 23 |
| 单份棋谱最多重复次数 | 46 | 16 |

完整棋谱包含停着。对称去重只使用保持标准初始黑白布局的四种变换，避免把同一开局换个方向算成新变化。不同棋谱数量明显增加，但仍存在重复，不把 100 局当作 100 个独立局面样本，不推算 Elo 或统计显著性。

## 选步策略

- 前 12 次**实际落子**启用，停着不增加计数。按当前棋盘已占格数减 4 计算阶段。
- 初始温度 32、允许最大分差 64，二者随剩余开局落子次数线性下降；第 13 次落子起恢复正常搜索的最高分走法。
- 仅保留与最高分差距不超过当前上限的候选，用 `exp((候选分数−最高分)/当前温度)` 加权抽选。
- 已精确求解、候选含终局分数、只有一个合格候选时不随机。评分是模型的搜索估分，分差限制不等于真实子差损失保证。
- 在完整完成的一轮根搜索上选步，保留全部候选评分；搜索、模型推理、置换表界限不变。每局使用不同种子，按棋盘哈希混合，候选按落点排序后抽样。

本次共 **296 次**进入多候选抽样，其中 **68 次**选中了当前评分略低的走法，观察到的最大分差为 **57 个估分单位**。其余抽样仍选中最高分或同分走法。种子、候选评分、温度、允许分差、实际分差和是否抽样均逐步保存，独立 Python 实现复核了每次选择。

默认参数先根据实际候选分布确定，再冻结进行本次 100 局。最初检查的 16/32 温度/分差窗口在部分局面只保留一个候选，未作为正式参数；没有根据本次胜负继续调参。

## 对战与复核

双方每步各 50ms，最大深度 64、等级 2，交换黑白各 50 局，标准四子初始棋盘自行走棋，不预设开局、不使用开局库。仅新版本启用随机策略，原版 v1.1 保持原选步逻辑。两个原生库各运行于独立常驻进程，逐步逐局顺序运行，每局开始清空双方置换表、局内跨步复用。模型分别为原版 v1 与行棋方模型 v1.2。

全部 **100 局、6,041 个动作**已重放，复核合法走法、停着、终局、子差、胜负、选步引擎；同时独立审计加权选择与种子、分差限制、对称去重，并重新汇总搜索统计。

完整记录见 [v1.3-vs-v1.1-nnue.json](v1.3-vs-v1.1-nnue.json)，冻结校验清单见 [v1.3-baseline.json](v1.3-baseline.json)。旧版本权重和历史报告未覆盖，v1.2 源码已单独归档。

## 使用与复现

```sh
cmake -S . -B .build/native -DCMAKE_BUILD_TYPE=Release
cmake --build .build/native -j 2
.build/native/otello selfplay --network models/nnue256-v1.2.otnnue --time 50
.build/native/otello analyze --network models/nnue256-v1.2.otnnue --variety on --seed 123
.build/native/otello analyze --network models/nnue256-v1.2.otnnue --variety off
```

NNUE 自对弈默认启用，未给种子时生成并输出新种子。分析默认输出最高分走法；`--variety off`、开局落子数 0 或温度 0 可以禁用。上述正常搜索行为针对 level 1/2，level 0 另有原先的入门选步逻辑。C ABI 对弈调用 `ot_nnue_play`，分析调用 `ot_nnue_search`；新接口示例见 [nnue_ffi.py](../examples/nnue_ffi.py)。

重跑对战前按 [v1.2 复现步骤](v1.2-comparison.md#重现)重建冻结的 v1.1，然后构建 `.build/native-v1.3`：

```sh
cmake -S . -B .build/native-v1.3 -DCMAKE_BUILD_TYPE=Release
cmake --build .build/native-v1.3 -j 2
npm run training:baseline:v1.3 -- --output .build/v1.3-repeat.json
npm run training:watch:v1.3
npm run test:baseline
```

固定候选评分和种子可复核抽样；限时搜索可能完成不同深度，所以完整对局的复核依据为保存的候选评分和棋谱。
