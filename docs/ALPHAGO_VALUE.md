# 借鉴 AlphaGo 的价值输出

## 原论文核对

2016 AlphaGo 使用独立价值网络，末端为全连接 256 维 ReLU，再接一个 tanh 标量。标签是从行棋方视角记录的终局胜负 ±1，用均方误差训练，并非预测赢多少目。价值训练数据来自策略网络自对弈；论文还特别处理了一局内多个局面的强相关问题。[原论文 Methods 与价值训练部分](https://deepmind-media.storage.googleapis.com/alphago/AlphaGoNaturePaper.pdf)

AlphaGo Zero 将策略与价值共用残差主干。价值分支为 `1×1 Conv(1通道) → BN → ReLU → Flatten → FC256 → ReLU → FC1 → tanh`；价值拟合自对弈终局结果，策略拟合 MCTS 搜索分布，二者联合训练。总损失包含价值 MSE、策略交叉熵和 L2 正则。[原论文 Methods、公式 1](https://ai6034.mit.edu/wiki/images/Nature24270_AlphaGoZero.pdf)

所以，胜／平／负三分类是另一种可选设计，并非上述论文的原样结构。更直接的借鉴是保留单标量输出，先改变目标语义。

## 对本项目的实验设计

已批准的 v1.8 仍以最终子差/64 作为价值目标。本次默认提升不改动它。下一候选应独立命名，与 v1.8 比较。

第一项消融不扩大主干，不加阶段头，保留现有策略分支；先冻结共享特征层与策略参数，只重新拟合单标量价值头：

```text
行棋方排列的 512 维共享特征
  ├─ 现有策略分支 512→32→65，冻结
  └─ 价值分支 512→1→tanh，拟合最终胜负
```

这是适配 NNUE 的轻量实验，不是论文卷积网络的复现。若固定特征不足，再单独考虑带策略损失的共享主干联合训练；不在第一项消融中同时更换主干结构。

- 训练标签：`z = sign(最终黑方子差 × 当前行棋方)`，胜 +1、平 0、负 −1。现有缓存已有最终子差，可确定性转换，冻结开局分组与评估集。
- 价值损失：`mean((v-z)^2)`；不再使用“平均子差误差”评价该新目标，报告胜负结果 MSE、校准与实际对战。
- 解释：`v ≈ P(胜)-P(负)`。对有和棋的黑白棋，`(v+1)/2` 是胜一分、平半分的期望得分，不一定等于纯胜率。
- MCTS：叶节点用上述 v，终局也回传胜 +1、平 0、负 −1，换行棋方逐层反号，停着同样处理。不能保留原终局子差/64，否则网络与终局奖励不在同一语义上。
- 模型格式必须标记价值目标（新 magic 或显式版本字段），模型身份与缓存失效检查也包含该目标。禁止仅将旧字节重新命名来宣称是胜负模型。
- 精确终局的外部展示仍可另外保留实际子差；不能把胜负回传的 ±1 再乘 64 当成真实子差。

策略标签目前来自棋谱落点，与 Zero 的 MCTS 访问分布标签有区别。可先用现有棋谱验证价值目标的影响，再考虑保存自对弈 `(局面, 根访问分布, 终局胜负)` 的闭环训练。这属于后续数据流程，不能将当前监督棋谱实验称为 AlphaGo Zero 自我对弈训练。

验证至少包含：新旧格式隔离、颜色/行棋方视角、平局、强制停着、终局回传、固定模拟数及等时限对照。不同时间预算分别统计；获批准前不替换 v1.8 默认基线。

## v1.9 实施状态

已按上述方案训练独立候选 `models/nnue256-outcome-v1.9.otnnue`：只更新 513 个价值头参数，共享特征与策略分支的量化字节完全保留。采用 `OTNNUE4` 标记胜负语义；终局和精确求解使用胜／平／负回传，找到已证明的必胜分支即可证明父节点必胜，选择时区分已证明必胜与四舍五入为 1 的网络估计。

训练与原生推理、格式、终局及旧模型兼容检查已通过。与冻结 v1.8 的每步 1 秒、20 局对照单独记录；这仍是候选，默认基线为 v1.8。完整结果发布到 `models/v1.9-outcome-vs-v1.8-1s.json` 后，由 `scripts/verify-outcome-experiment.py` 核对源码快照、模型字节与逐步棋谱。

用户随后批准换基线：v1.9 已作为新默认发布，记录见 `models/v1.9-default.json`。上文的未批准状态记录的是实验期间；原始训练与对战报告保持不变。
